# MediaGrabber

常驻 Windows 托盘的媒体抓取工具。把网页里和屏幕上的图片、视频保存到 D 盘。

**全部四个阶段已完成。现在是一个双击就能用的 exe。**

两种模式的区别：

| | 模式一 · 浏览器模式 | 模式二 · 通用模式 |
|---|---|---|
| 怎么用 | 托盘菜单 →「浏览器模式（主窗口）」 | 按 `Ctrl + Alt + S` |
| 抓什么 | 网页里的**真实图片文件** | 屏幕上**显示出来的像素** |
| 拿到的是 | 原始文件，原分辨率 | 屏幕截图，屏幕分辨率 |
| 适合 | 图库、商品页、社交媒体 | PDF 阅读器、本地软件、抓不到源文件的场景 |

---

## 一、怎么用

**双击 `MediaGrabber.exe`** 就行。没有黑窗口，右下角托盘区会出现一个蓝色相机图标。

不需要装 Python，不需要装任何依赖，换台电脑拷过去也能跑。启动约 3 秒
（单文件 exe 每次要把内容解压到临时目录，这是它唯一的代价）。

### exe 放在哪里很重要

`config.json`、`logs`、`chrome-profile` 这三样都会生成在 **exe 旁边**。
其中 `chrome-profile` 存着你在受控浏览器里的登录状态。

所以：**把 exe 放在项目根目录**（`D:\Claude Code-Media Grabber\`），
它就能直接接着用你现在的配置和登录状态，不用重新登录一遍。

放到别的地方也能用，只是那边会重新生成一套空的，需要重新登录网站。

### 出问题时的第一手段

在命令行里执行（或者建个快捷方式，在「目标」末尾加上 ` --selftest`）：

```
MediaGrabber.exe --selftest
```

它会把每一项依赖都真的调用一次，然后弹窗告诉你结果。
打包最容易出的毛病就是「少收了某个文件」——比如浏览器模式打不开，
自检当场就能看出来是不是 playwright 的问题。这个模式不占用单实例端口，
程序正开着的时候也能跑。

## 二、模式二 · 通用模式（屏幕框选）

按 `Ctrl + Alt + S` 唤起。画面会立刻冻结，底下的内容再动也不影响你框。
有两个子模式，随时按 `Tab` 切换，屏幕上方一直显示着当前能按哪些键。

### 手动框选（默认）

| 操作 | 说明 |
|---|---|
| 按住左键拖动 | 画选区，鼠标旁实时显示**物理像素**尺寸 |
| 松开左键 | 立刻保存为 PNG，右下角弹出提示条 |
| `Tab` | 切到自动识别 |
| `A` 键 | 捕获鼠标所在那块屏的**整屏**（主要用于验证坐标，见第五节） |
| 右键 | 取消当前这一框，遮罩不关 |
| `Esc` | 退出遮罩，什么都不存 |

### 自动识别（指哪算哪）

按 `Tab` 进入。**鼠标移到哪，就分析哪一块**——不是一进去就满屏黄框。

| 操作 | 说明 |
|---|---|
| 移动鼠标 | 鼠标底下那块用**黄色虚线**框出来，旁边显示尺寸和「第几层」 |
| **滚轮** | 换选区大小：往上滚变大（小块 → 整张图 → 更大的容器），往下滚变小 |
| 单击 | 选中，变成**绿色实线**，框内恢复亮度，左上角标序号 |
| 点已选中的框 | 取消它 |
| `Backspace` | 撤销最后一次选中（比点回去取消快） |
| 拖动 | 自己补画一个框，补的是蓝色，直接算选中 |
| `Enter` | 把选中的**一次性全部保存**，右下角汇总提示「已保存 N 张」 |
| `Tab` | 切回手动 |
| `Esc` | 退出，什么都不存 |

**滚轮是这里最该记住的操作。** 一张图有时会被切成两半（图片中间有明暗分界时），
往上滚一格就是完整的那张——不用调参数、不用重来。反过来，想只要图里的一小块，
往下滚就行。

其它几点：

- 进去的头一瞬间提示条会显示「正在分析画面…」，那期间移动鼠标没反应，
  半秒之内就好。这期间也可以直接拖框。
- **识别不可能百分百准。** 滚轮解决不了的，就自己拖框补上，
  两种框能混着用，最后一起按 `Enter`。
- 三条路一起找边界：轮廓、投影、颜色。第三条专门对付浅色背景上的浅色图
  ——那种图的边缘梯度太小，靠边缘检测无论怎么调阈值都检不出来。

文件存到：`D:\MediaGrabber\Screen\<今天的日期>\screen_20260830_143052.png`

### 主窗口和设置

- **双击托盘图标**：打开主窗口。上面有两个标签页：「浏览器模式」和「历史记录」，
  右上角有「设置」按钮。
- **历史记录**：列出存过的所有文件（时间、来源、尺寸、路径、缩略图）。
  **双击任意一条就能在资源管理器里定位到那个文件**；右键还能直接打开文件或复制路径。
  文件被你删掉的记录会标灰显示，不会凭空消失。
- **设置**：托盘菜单里也能直接打开。分 5 页，每一项底下都写了一句人话说明。
  改完点保存立刻生效，**没有需要重启的项目**（热键和日志级别会自动重新装载）。

## 三、模式一 · 浏览器模式（抓网页原图）

托盘图标右键 →「浏览器模式（主窗口）」，或者双击托盘图标。

### 用法

1. **点「启动浏览器」**
   会打开一个**专用的 Chrome 窗口**（不是你平时那个）。左上角指示灯：
   灰 = 未连接，黄 = 连接中，绿 = 已连接。

2. **在那个 Chrome 里打开你要抓的页面**
   需要登录的网站，就在这个窗口里登录一次。登录状态会一直保留。

3. **切回 MediaGrabber，点「扫描当前页面」**
   缩略图网格会列出扫到的图片和视频。

4. **勾选想要的，点「下载选中」**
   底部有进度条，完成后显示「成功 N 张」。失败的卡片是红框，鼠标悬停看原因。

文件存到：`D:\MediaGrabber\<域名>\<今天的日期>\`

### 为什么要单独登录一次

从 Chrome 136 起，`--remote-debugging-port` 参数在针对**默认配置目录**时会被直接忽略，
必须搭配一个指向非标准目录的 `--user-data-dir`。所以受控浏览器用的是独立的
`chrome-profile` 文件夹，没法复用你平时那个 Chrome 的登录状态。

**这是 Chrome 的安全策略，不是 bug，也不该绕过。**
好消息是：登录一次就够了，`chrome-profile` 会一直保留，以后不用重复登录。

点「登录状态」按钮可以看到当前有哪些网站存了 cookie，也可以一键清除全部登录数据。

### 界面上的几个说明

- **尺寸未知的项不会被筛掉。** 懒加载的图在扫描那一刻还没真正加载，
  拿不到尺寸。这类项即使你把「最小尺寸」滑块拉很高也依然显示——
  否则最想要的那些图恰恰会被筛没。缩略图加载出来后会自动补上真实尺寸。
- **`srcset` 图片的尺寸是还原过的。** 浏览器对 srcset 图片报的
  `naturalWidth` 是按显示密度换算过的（一张 1400px 宽的图可能报成 1036），
  程序会用 `srcset` 里的 `w` 描述符还原成真实文件尺寸。宽度精确，高度可能差 1 像素。
- **分片流视频和 DRM 内容会灰掉，不能勾选。** B 站、优酷这类网站的视频是几百个
  `.ts` 小片段拼出来的（地址是 `blob:` 开头），需要 ffmpeg 合并，不在本工具范围内。
  只支持 `<video src="xxx.mp4">` 这种直链视频。
- **缩略图会额外产生一次请求**（多数命中浏览器缓存，很快）。网络很慢又不在意预览的话，
  把 `config.json` 里的 `browser.load_thumbnails` 改成 `false` 就不抓了。

## 四、几个说明

**存下来的是屏幕像素，不是原图。**
通用模式拿到的只能是屏幕上显示出来的像素。你的屏幕是 2560×1600，那么屏幕上
显示的一张 4K 图，存下来就是它在屏幕上占的那块区域的尺寸。这是操作系统层面
的限制，绕不过去。想拿原始文件用**浏览器模式**（第三节）。

**内容重复会自动跳过。**
按文件内容的 MD5 判断。截了两张一模一样的图，第二张不会存，提示条会显示
「已存在，已跳过」并告诉你原文件在哪。你把原文件删掉之后，再截同样的内容
就会正常保存。

**同名文件绝不覆盖。**
同一秒内连截多张会自动加 `_1` `_2` 后缀。

**跨屏框选暂不支持。**
从一块屏拖到另一块屏时，选区会停在起始那块屏的边缘。
（自动模式不受影响：两块屏各自分析，选中的按一次 `Enter` 会一起保存。）

## 五、验证坐标准不准（阶段 1 的重点验收项）

150% 缩放下，1 个逻辑像素 = 1.5 个物理像素。偏一两个像素肉眼看不出来，
所以要用标定图量化验证。

### 测试 A · 整屏精确捕获（最重要，一步就能发现缩放系数错误）

1. 先把程序跑起来（双击 `MediaGrabber.exe`，或者双击 `2-启动程序.bat` 从源码跑）
2. 双击 `3-显示标定图.bat`
   → 屏幕会被一张带网格和三个彩色方块（红/绿/蓝）的图铺满
3. 按 `Ctrl + Alt + S`
   → 屏幕变暗，出现十字光标
4. 按 `A` 键
   → 屏幕恢复，右下角弹出提示条说存到哪了
5. 双击 `4-比对坐标.bat`
   → 它会自动找到你刚存的那张图，不用你复制路径

**要看到的结果**：
```
[  通过  ] 尺寸完全一致：2560 x 1600
[  通过  ] 完美：尺寸、位置、缩放全部精确一致。
```

尺寸必须正好是 **2560 × 1600**。
如果是 1707×1067，说明缩放系数丢了；如果是 3840×2400，说明乘了两次。

> 标定图还在屏幕上挡着？点它一下再按 `Esc` 就关掉了。

### 测试 B · 手动框选的偏移

标定图还开着的话（关了就再双击一次 `3-显示标定图.bat`），
用鼠标随便框一块区域，**框住至少一个彩色方块**，松手。
然后双击 `4-比对坐标.bat`。

**要看到的结果**：
```
[  通过  ] 缩放系数正确（三个标记位移完全一致，标记尺寸也没变）。
           截图对应的是标定图上从 (xxx, yyy) 开始的区域。
```

它报的 `(xxx, yyy)` 应该和你框的左上角位置对得上——
对照标定图上印的网格数字看就行，差个十几像素是手抖，正常。

**要是看到 `[  失败  ] 缩放系数有问题！`**，说明图被拉伸了，
把 `logs` 目录下当天的日志发给我。

### 测试 C · 贴边

贴着屏幕最右边、最下边框一条窄条。不能报错，存出来的图右边缘不能有黑边。
（离边缘 2 个逻辑像素以内会自动吸附到边缘，日志里会记录吸附了哪几条边。）

## 六、出问题了怎么办

所有异常都会写进 `logs\mediagrabber.log`（当天的日志永远是这个名字，
更早的是 `mediagrabber-2026-08-29.log` 这种）。托盘菜单里有「打开日志目录」。

按这个格式发给我：

```
【现象】按了 Ctrl+Alt+S 没反应
【我已经试过】重启了程序，托盘图标是在的
```

再把当天的日志文件一起发过来。

### 几个常见情况

**控制台刷出一堆 `libpng warning: iCCP: known incorrect sRGB profile`**
可以无视。这是 PySide6 自带的 Windows 主题在第一次显示窗口时，加载它自己的
图标资源产生的警告——那些图标里的色彩描述块不规范。跟你的图片、跟本程序的
代码都没有关系（已经验证过：截图和 PNG 保存这条路径一条警告都不产生）。
每次启动会出现约 40 行，之后就不再出现了。

**按热键没反应**
日志里搜「全局热键注册成功」。没有这行就是注册失败了；有这行还是没反应，
多半是热键被别的软件占用了（pynput 检测不到这种情况）。改
`config.json` 里的 `hotkey.capture` 换一个组合，比如 `<ctrl>+<alt>+d`。

**提示「已经有一个 MediaGrabber 在运行」**
从托盘图标右键退出；或者任务管理器里找 `MediaGrabber.exe` 结束掉
（从源码跑的话找 `python.exe`）。
程序用 127.0.0.1:52341 端口做单实例检测，两个实例同时抢热键会导致
「有时有反应有时没有」这种极难排查的问题。

**点「启动浏览器」后一直连不上**
首要怀疑对象是**代理软件**（Clash、v2ray 之类）。它们会设置 HTTP_PROXY 环境变量，
导致连本机的 127.0.0.1 都被送去走代理。本程序已经强制让本机地址绕过代理，
所以正常不会遇到；万一还是不行，日志里搜「调试端口」看具体报什么。

另一个常见原因：**你已经开着普通的 Chrome**。Chrome 会把新窗口交给已有进程处理，
导致调试端口开不起来。把所有 Chrome 窗口关掉再试。

**下载报 `connect ETIMEDOUT` / `ECONNRESET`（图在页面上明明能看到）**
已经自动处理了，正常不用管。原理写在这里备查：

下载有两条通道。首选 `page.request`，它共享浏览器的完整会话，登录站点全靠它。
但它是 Playwright 的 Node 进程自己发的请求，**不走 Chrome 的网络栈**——
不用 Chrome 的代理、自己做 DNS。所以在 DNS 被污染或者要靠代理才能访问的
网络环境里，页面上图片显示得好好的，这条通道却连不上。

这时程序会自动降级到第二条通道 httpx，它会读 `HTTP_PROXY` 环境变量走系统代理，
DNS 由代理远程解析，正好绕开上面两个问题。而且某个域名一旦在第一条通道上栽过，
后续同域名的资源直接走第二条，不会每张图都白等一次超时。

程序会**像 Chrome 一样直接读 Windows 系统代理设置**，不依赖 `HTTP_PROXY`
环境变量——因为代理软件常常只改系统设置不设环境变量，而且从资源管理器
双击启动的程序也继承不到终端里的环境变量。

**如果两条通道都失败**，提示里会写明当前用的是哪个代理、从哪读到的。
这时检查：代理软件（Clash 等）是不是没开、是不是刚切换过节点。

**少数图片一直报 403，重新扫描也没用**
多半是网站自己的界面素材（图标、按钮、装饰图），网站本来就不允许直接下载，
这不是程序的问题。内容图报 403 才值得关注（那可能是防盗链或直链过期）。

**扫描不到图 / 扫到的比页面上看到的少**
先把页面往下滚到底再扫——懒加载的图没滚到就不会加载。
另外「最小尺寸」滑块拉太高也会筛掉东西（尺寸未知的项不受影响）。

**框选位置偏了**
日志里搜 `[拖框]`，会看到完整的换算过程：逻辑坐标 → 缩放系数 → 物理坐标。
再搜「交叉验证」，看有没有失败记录。把这几行发给我。

**按 Tab 之后移动鼠标没有预览框**
屏幕上方那行状态文字会告诉你是哪种情况：

- 「正在分析画面…」→ 还没算完，等半秒。一直不变就是卡住了，把日志发我
- 「分析失败：没装 opencv-python」→ 双击 `1-环境自检.bat` 看看
- 「把鼠标移到想要的图片上」→ 索引好了，但鼠标位置那块什么都没找到。
  换个位置试试（往图片中间挪），或者直接自己拖框

日志里搜「候选索引建好」，能看到找到了多少个候选、花了多久。

**框的大小老是不对**
先滚滚轮——多数情况滚一两格就对了。滚遍所有层级都不合适，就自己拖框补。
如果是**整片区域都框不出来**（滚轮也没有别的层级），去设置面板把两个
「边缘检测」阈值调小。如果是**一张图老被切成两半**，把「模糊强度」调大。

**识别出来的框比图片大了一两个像素**
正常。边缘检测把颜色跳变的那一条也算进去了。宁可多带一像素背景，
也好过把图片自己的边缘切掉。

## 七、配置

**优先用设置面板改**（托盘菜单 →「设置」，或主窗口右上角）。
每一项底下都有说明，还有格式校验，改完立刻生效。

`config.json` 在项目根目录，也可以直接改（改完要重启）。
文件被改坏了不会导致程序起不来——会自动备份成 `config.json.bak` 并重建。

常用项：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `save.root` | `D:\MediaGrabber` | 保存根目录 |
| `save.split_by_date` | `true` | 是否按日期建子文件夹 |

| 配置项 | 默认值 | 什么时候调 |
|---|---|---|
| `detector.canny_low` / `canny_high` | `50` / `150` | 整片区域都框不出来 → 两个都调小 |

## 九、已知的不足

**自动识别不可能百分百准。**
滚轮把「该选多大」这个歧义交给了你，所以比第一版好用得多，但仍有搞不定的：
- 图片和图片**紧挨着**（间隔小于 5 像素）时，可能被连成一整块
- 完全没有边界的图（比如照片直接铺在同色背景上，边上还带渐变阴影）
- 半透明叠在别的内容上的图

这些情况滚轮也救不回来，直接自己拖框最快。

**缩略图加载没有进度提示。**
浏览器模式下，一整页几十张图、并发 4、还要过代理，要二三十秒才陆续出齐。
这期间卡片一直显示「加载中…」，看着像卡住了。抓取本身是正常的
（实测 14/14 取回并解码成功），纯粹是界面缺少反馈。

**跨屏框选。**
从一块屏拖到另一块屏时，选区会停在起始那块屏的边缘。
（自动模式下不受影响：两块屏各自识别，选中的框按一次 `Enter` 会一起保存。）

**网站自己的界面素材会被扫进来。**
CSS 背景里的 SVG 已经排除了，但仍可能混进少量非内容图。这类资源常常返回 403
（网站本来就不允许直接下载），勾选下载会失败——这不是程序的问题。

### 2026-08-31 · 阶段 4 完成（打包成 exe）

`build.py` + `mediagrabber.spec`，一条命令打出 **131 MB 的单文件 exe**，
双击即用，启动约 3 秒。

打包过程中处理的问题：

- **playwright 不是纯 Python 包。** 它靠一个自带的 Node.js 进程干活
  （`playwright/driver/`，101 MB）。PyInstaller 只分析 import 语句，
  根本看不见这些文件。收不全的后果很隐蔽：程序能启动、框选也正常，
  唯独点「启动浏览器」报 `Executable doesn't exist`——**只在打包后才出现的故障**。
  用 `collect_all("playwright")` 解决。
- **去掉黑窗口后 `sys.stderr` 变成 `None`。** 日志模块往它身上装 StreamHandler
  会在第一条日志时炸掉；`print(..., file=sys.stderr)` 也会崩。
  两处都加了判断。顺带把「程序已在运行」这类提示改成了**弹窗**——
  没有控制台的话，双击之后什么都不发生，你只能一脸茫然。
- **新增 `--selftest`**：打包后出问题时的第一手段。把每项依赖都真的调用一次，
  结果写日志 + 弹窗。不占单实例端口，程序开着也能跑。
- 排除了用不到的 Qt 模块（QML、Quick、3D、多媒体等），PySide6 装出来 207 MB，
  实际只用 QtCore/QtGui/QtWidgets。
- 图标改由 `ui/appicon.py` 统一提供，托盘图标和 exe 图标是同一份代码画的，
  不会出现两处不一致。

关于 DPI：exe 里 `SetProcessDpiAwarenessContext` 会失败、降级到旧 API，
因为 PyInstaller 生成的 exe 自带 manifest，进程启动时**已经**是 Per-Monitor V2 了。
最终生效的模式是对的，坐标自检也通过（逻辑 1707×1067 → 物理 2560×1600）。

### 2026-08-31 · 自动识别改成点选式（推翻重做）

你反馈第一版「很大程度上不准确：一些图识别不到，一些边界清晰的也判断失误，
甚至把一张图识别成两部分」，并提出「点哪个区域就判断那个区域」。照这个思路重做了。

**为什么第一版必然不准**：整块屏幕共用一套阈值。调高 → 浅色背景上的浅色图
检不出边缘（漏检）；调低 → 图片内部的明暗分界也被当成边界（一张切两半）；
取中间 → 两种毛病各来一半。这不是参数没调好，是「先扫全屏再靠阈值猜哪些是图」
这个思路的天花板。

**现在的做法**：用鼠标位置当锚点，问题从「屏幕上哪些是图」变成「包住这个点的
边界在哪」，后者好解得多。于是筛选整个不要了（筛选正是漏检的来源），
改成三条路一起找边界：

- **轮廓法**：多组阈值各跑一遍 Canny，结果全丢进候选池
- **投影法**：从鼠标向四个方向扫，找第一条横跨够长的边缘线。
  专治边框没闭合——轮廓法这时会失败
- **颜色漫延法**：从鼠标向外扩散颜色相近的像素。
  专治低对比度——浅灰底上的浅灰块灰度只差 13，Canny 无论如何都检不出来

三边结果按面积排成层级，**滚轮切换**。一张图被切成两半时往上滚一格就是完整的。

自测：合成场景 6 组全部命中（含低对比度、内部有强分界线、紧挨着的两张图），
单次查询 6.6 毫秒，进入自动模式时的预计算 50 毫秒。

顺带修掉的：
- **numpy 数组悬空指针导致进程崩溃** —— `np.frombuffer(QImage.constBits())`
  得到的数组不拥有内存，只是 QImage 缓冲区上的视图。以前用完就丢没事，
  现在要把它一直存着给颜色漫延用，QImage 一被回收就成了野指针，
  进程直接「访问违例」退出，连异常都抛不出来。加 `.copy()` 解决。
- 关闭遮罩时对未连接的信号调 disconnect，PySide6 会往控制台打红字警告。

界面上的变化：满屏黄框没有了（它没帮上忙，反而挡视线）；
`Ctrl+A` 去掉了（没有全局候选列表可全选）；新增 `Backspace` 撤销上一次选中。

开发过程中发现并解决的问题：

- **Canny 出来的是「线条」，不是「区域」** —— 直接对它 `findContours` 得到的是
  绕着线条一圈的细环，`contourArea` 接近 0，矩形度判断永远不及格。
  必须先做一次形态学**闭运算**把断边接上，轮廓才会围出一块真正的区域。
- **`RETR_EXTERNAL` 会吞掉容器里的图** —— 改用 `RETR_LIST` 拿全部轮廓。
- **新增的配置字段必须同步加进 `config.py` 的 DEFAULTS** —— 否则设置面板存进
  `config.json` 的值会在下次启动时被合并逻辑当成「多余字段」丢掉，
  表现为「设置改了，重启就变回去了」。
- **`A` 和 `Ctrl+A` 是两个功能**（整屏捕获 / 全选候选），判断顺序不能反。

浏览器模式全部功能：受控 Chrome 启动 + CDP 连接、页面扫描、缩略图网格、

开发过程中修掉的几个问题（都是实测发现的，不是猜的）：

- **系统代理劫持本机连接** —— httpx 默认会把 `127.0.0.1:9222` 也送去走代理，
  代理返回 502，表现为「Chrome 起来了却连不上」。探测端口时强制不走代理。
- **`page.request` 不走 Chrome 网络栈** —— DNS 被污染时页面上图片显示正常，
  下载却超时。补上 httpx 兜底通道（CLAUDE.md 第 6.3 节本就要求的降级）。
- **代理探测不能只看环境变量** —— 环境变量不持久，双击启动的进程继承不到。
  改成像 Chrome 一样读 Windows 系统代理设置。
- **403 直接判死** —— 没试第二条通道就放弃，导致「重新扫描也没用」。
  改成 4xx 时换通道再试，两条都失败才判死。
- **`naturalWidth` 对 srcset 图片不可信** —— 会被密度换算，且两个方向都会偏。
  用 `w` 描述符还原真实尺寸，否则尺寸滑块会误筛掉大图。
- **占位图正则误杀正常图片** —— 裸关键词匹配会把 `lazy.png` 当成占位图丢掉。
