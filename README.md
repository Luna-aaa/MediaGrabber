# MediaGrabber

常驻 Windows 托盘的媒体抓取工具。把网页里和屏幕上的图片、视频保存到 D 盘。

**当前进度：阶段 1（通用模式 · 手动框选）、阶段 2（浏览器模式）已完成。**

两种模式的区别：

| | 模式一 · 浏览器模式 | 模式二 · 通用模式 |
|---|---|---|
| 怎么用 | 托盘菜单 →「浏览器模式（主窗口）」 | 按 `Ctrl + Alt + S` |
| 抓什么 | 网页里的**真实图片文件** | 屏幕上**显示出来的像素** |
| 拿到的是 | 原始文件，原分辨率 | 屏幕截图，屏幕分辨率 |
| 适合 | 图库、商品页、社交媒体 | PDF 阅读器、本地软件、抓不到源文件的场景 |

## 三、模式一 · 浏览器模式（抓网页原图）

托盘图标右键 →「浏览器模式（主窗口）」，或者双击托盘图标。

### 用法

1. **点「启动浏览器」**
   会打开一个**专用的 Chrome 窗口**（不是你平时那个）。左上角指示灯：
   灰 = 未连接，黄 = 连接中，绿 = 已连接。

2. **在那个 Chrome 里打开你要抓的页面**
   需要登录的网站，就在这个窗口里登录一次。登录状态会一直保留。

3. **切回 MediaGrabber，点「扫描当前页面」**
   缩略图网格会列出扫到的图片和视频。

4. **勾选想要的，点「下载选中」**
   底部有进度条，完成后显示「成功 N 张」。失败的卡片是红框，鼠标悬停看原因。

文件存到：`D:\MediaGrabber\<域名>\<今天的日期>\`

### 为什么要单独登录一次

从 Chrome 136 起，`--remote-debugging-port` 参数在针对**默认配置目录**时会被直接忽略，
必须搭配一个指向非标准目录的 `--user-data-dir`。所以受控浏览器用的是独立的
`chrome-profile` 文件夹，没法复用你平时那个 Chrome 的登录状态。

**这是 Chrome 的安全策略，不是 bug，也不该绕过。**
好消息是：登录一次就够了，`chrome-profile` 会一直保留，以后不用重复登录。

点「登录状态」按钮可以看到当前有哪些网站存了 cookie，也可以一键清除全部登录数据。

### 界面上的几个说明

- **尺寸未知的项不会被筛掉。** 懒加载的图在扫描那一刻还没真正加载，
  拿不到尺寸。这类项即使你把「最小尺寸」滑块拉很高也依然显示——
  否则最想要的那些图恰恰会被筛没。缩略图加载出来后会自动补上真实尺寸。
- **`srcset` 图片的尺寸是还原过的。** 浏览器对 srcset 图片报的
  `naturalWidth` 是按显示密度换算过的（一张 1400px 宽的图可能报成 1036），
  程序会用 `srcset` 里的 `w` 描述符还原成真实文件尺寸。宽度精确，高度可能差 1 像素。
- **分片流视频和 DRM 内容会灰掉，不能勾选。** B 站、优酷这类网站的视频是几百个
  `.ts` 小片段拼出来的（地址是 `blob:` 开头），需要 ffmpeg 合并，不在本工具范围内。
  只支持 `<video src="xxx.mp4">` 这种直链视频。
- **缩略图会额外产生一次请求**（多数命中浏览器缓存，很快）。网络很慢又不在意预览的话，
  把 `config.json` 里的 `browser.load_thumbnails` 改成 `false` 就不抓了。

## 四、几个说明

**存下来的是屏幕像素，不是原图。**
通用模式拿到的只能是屏幕上显示出来的像素。你的屏幕是 2560×1600，那么屏幕上
显示的一张 4K 图，存下来就是它在屏幕上占的那块区域的尺寸。这是操作系统层面
的限制，绕不过去。想拿原始文件用**浏览器模式**（第三节）。

**内容重复会自动跳过。**
按文件内容的 MD5 判断。截了两张一模一样的图，第二张不会存，提示条会显示
「已存在，已跳过」并告诉你原文件在哪。你把原文件删掉之后，再截同样的内容
就会正常保存。

**同名文件绝不覆盖。**
同一秒内连截多张会自动加 `_1` `_2` 后缀。

**跨屏框选暂不支持。**
从一块屏拖到另一块屏时，选区会停在起始那块屏的边缘。阶段 3 再处理。

## 五、验证坐标准不准（阶段 1 的重点验收项）

150% 缩放下，1 个逻辑像素 = 1.5 个物理像素。偏一两个像素肉眼看不出来，
所以要用标定图量化验证。

### 测试 A · 整屏精确捕获（最重要，一步就能发现缩放系数错误）

1. 先双击 `2-启动程序.bat`，让程序跑着（那个黑窗口别关）
2. 双击 `3-显示标定图.bat`
   → 屏幕会被一张带网格和三个彩色方块（红/绿/蓝）的图铺满
3. 按 `Ctrl + Alt + S`
   → 屏幕变暗，出现十字光标
4. 按 `A` 键
   → 屏幕恢复，右下角弹出提示条说存到哪了
5. 双击 `4-比对坐标.bat`
   → 它会自动找到你刚存的那张图，不用你复制路径

**要看到的结果**：
```
[  通过  ] 尺寸完全一致：2560 x 1600
[  通过  ] 完美：尺寸、位置、缩放全部精确一致。
```

尺寸必须正好是 **2560 × 1600**。
如果是 1707×1067，说明缩放系数丢了；如果是 3840×2400，说明乘了两次。

> 标定图还在屏幕上挡着？点它一下再按 `Esc` 就关掉了。

### 测试 B · 手动框选的偏移

标定图还开着的话（关了就再双击一次 `3-显示标定图.bat`），
用鼠标随便框一块区域，**框住至少一个彩色方块**，松手。
然后双击 `4-比对坐标.bat`。

**要看到的结果**：
```
[  通过  ] 缩放系数正确（三个标记位移完全一致，标记尺寸也没变）。
           截图对应的是标定图上从 (xxx, yyy) 开始的区域。
```

它报的 `(xxx, yyy)` 应该和你框的左上角位置对得上——
对照标定图上印的网格数字看就行，差个十几像素是手抖，正常。

**要是看到 `[  失败  ] 缩放系数有问题！`**，说明图被拉伸了，
把 `logs` 目录下当天的日志发给我。

### 测试 C · 贴边

贴着屏幕最右边、最下边框一条窄条。不能报错，存出来的图右边缘不能有黑边。
（离边缘 2 个逻辑像素以内会自动吸附到边缘，日志里会记录吸附了哪几条边。）

## 六、出问题了怎么办

所有异常都会写进 `logs\mediagrabber.log`（当天的日志永远是这个名字，
更早的是 `mediagrabber-2026-08-29.log` 这种）。托盘菜单里有「打开日志目录」。

按这个格式发给我：

```
【现象】按了 Ctrl+Alt+S 没反应
【我已经试过】重启了程序，托盘图标是在的
```

再把当天的日志文件一起发过来。

### 几个常见情况

**控制台刷出一堆 `libpng warning: iCCP: known incorrect sRGB profile`**
可以无视。这是 PySide6 自带的 Windows 主题在第一次显示窗口时，加载它自己的
图标资源产生的警告——那些图标里的色彩描述块不规范。跟你的图片、跟本程序的
代码都没有关系（已经验证过：截图和 PNG 保存这条路径一条警告都不产生）。
每次启动会出现约 40 行，之后就不再出现了。

**按热键没反应**
日志里搜「全局热键注册成功」。没有这行就是注册失败了；有这行还是没反应，
多半是热键被别的软件占用了（pynput 检测不到这种情况）。改
`config.json` 里的 `hotkey.capture` 换一个组合，比如 `<ctrl>+<alt>+d`。

**提示「已经有一个 MediaGrabber 在运行」**
任务管理器里找 `python.exe` 结束掉，或者从托盘图标右键退出。
程序用 127.0.0.1:52341 端口做单实例检测，两个实例同时抢热键会导致
「有时有反应有时没有」这种极难排查的问题。

**点「启动浏览器」后一直连不上**
首要怀疑对象是**代理软件**（Clash、v2ray 之类）。它们会设置 HTTP_PROXY 环境变量，
导致连本机的 127.0.0.1 都被送去走代理。本程序已经强制让本机地址绕过代理，
所以正常不会遇到；万一还是不行，日志里搜「调试端口」看具体报什么。

另一个常见原因：**你已经开着普通的 Chrome**。Chrome 会把新窗口交给已有进程处理，
导致调试端口开不起来。把所有 Chrome 窗口关掉再试。

**下载报 `connect ETIMEDOUT` / `ECONNRESET`（图在页面上明明能看到）**
已经自动处理了，正常不用管。原理写在这里备查：

下载有两条通道。首选 `page.request`，它共享浏览器的完整会话，登录站点全靠它。
但它是 Playwright 的 Node 进程自己发的请求，**不走 Chrome 的网络栈**——
不用 Chrome 的代理、自己做 DNS。所以在 DNS 被污染或者要靠代理才能访问的
网络环境里，页面上图片显示得好好的，这条通道却连不上。

这时程序会自动降级到第二条通道 httpx，它会读 `HTTP_PROXY` 环境变量走系统代理，
DNS 由代理远程解析，正好绕开上面两个问题。而且某个域名一旦在第一条通道上栽过，
后续同域名的资源直接走第二条，不会每张图都白等一次超时。

程序会**像 Chrome 一样直接读 Windows 系统代理设置**，不依赖 `HTTP_PROXY`
环境变量——因为代理软件常常只改系统设置不设环境变量，而且从资源管理器
双击启动的程序也继承不到终端里的环境变量。

**如果两条通道都失败**，提示里会写明当前用的是哪个代理、从哪读到的。
这时检查：代理软件（Clash 等）是不是没开、是不是刚切换过节点。

**少数图片一直报 403，重新扫描也没用**
多半是网站自己的界面素材（图标、按钮、装饰图），网站本来就不允许直接下载，
这不是程序的问题。内容图报 403 才值得关注（那可能是防盗链或直链过期）。

**扫描不到图 / 扫到的比页面上看到的少**
先把页面往下滚到底再扫——懒加载的图没滚到就不会加载。
另外「最小尺寸」滑块拉太高也会筛掉东西（尺寸未知的项不受影响）。

**框选位置偏了**
日志里搜 `[拖框]`，会看到完整的换算过程：逻辑坐标 → 缩放系数 → 物理坐标。
再搜「交叉验证」，看有没有失败记录。把这几行发给我。

## 七、配置

`config.json` 在项目根目录，首次运行自动生成。改完重启程序生效。
文件被改坏了不会导致程序起不来——会自动备份成 `config.json.bak` 并重建。

常用项：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `save.root` | `D:\MediaGrabber` | 保存根目录 |
| `save.split_by_date` | `true` | 是否按日期建子文件夹 |
| `save.dedupe_by_md5` | `true` | 是否按内容去重 |
| `hotkey.capture` | `<ctrl>+<alt>+s` | 框选热键。修饰键必须写成 `<ctrl>` `<alt>` `<shift>` |
| `screen.mask_opacity` | `120` | 未选中区域的压暗程度，0~255 |
| `screen.edge_snap_px` | `2` | 离边缘多近时自动吸附，设 0 关闭 |
| `log.level` | `INFO` | 排查问题时改成 `DEBUG` 能看到更多细节 |

## 十一、变更记录

### 2026-08-31 · 阶段 2 完成

浏览器模式全部功能：受控 Chrome 启动 + CDP 连接、页面扫描、缩略图网格、
批量下载、登录状态管理。

验收：pixabay（免登录）+ pixiv（需登录）均能正确批量下载。

开发过程中修掉的几个问题（都是实测发现的，不是猜的）：

- **系统代理劫持本机连接** —— httpx 默认会把 `127.0.0.1:9222` 也送去走代理，
  代理返回 502，表现为「Chrome 起来了却连不上」。探测端口时强制不走代理。
- **`page.request` 不走 Chrome 网络栈** —— DNS 被污染时页面上图片显示正常，
  下载却超时。补上 httpx 兜底通道（CLAUDE.md 第 6.3 节本就要求的降级）。
- **代理探测不能只看环境变量** —— 环境变量不持久，双击启动的进程继承不到。
  改成像 Chrome 一样读 Windows 系统代理设置。
- **403 直接判死** —— 没试第二条通道就放弃，导致「重新扫描也没用」。
  改成 4xx 时换通道再试，两条都失败才判死。
- **`naturalWidth` 对 srcset 图片不可信** —— 会被密度换算，且两个方向都会偏。
  用 `w` 描述符还原真实尺寸，否则尺寸滑块会误筛掉大图。
- **占位图正则误杀正常图片** —— 裸关键词匹配会把 `lazy.png` 当成占位图丢掉。
